Solution Documentation · Speech AI

Newspapers and scripts become audiowith local AI, zero cost per newspaper

Speech AI takes the Valor Econômico and Estadão PDFs plus text scripts and produces an executive HTML summary, a voice script and audio narrated in Portuguese. Since Sprint 13, the editorial content is written by a local AI model (Ollama, on this machine's GPU) instead of Anthropic's paid API — this document describes the solution, the path of each input file to output, and day-to-day operations.

Part 1 · Overview

Overview · Performance

From the 20-minute skill to local AI: three architectures, the same output

1) The original skill: Claude did everything — extraction, reading, writing and revising the HTML in 100 to 126 rounds. 2) The fast pipeline (Sprint 12): Python takes over extraction/assembly/verification; paid AI (Claude) only writes the content, in single-shot calls. 3) Local AI (Sprint 13): the same fast-pipeline architecture, but paid AI becomes Ollama running on this machine's GPU — AI cost drops to zero, time goes up.

Time from PDF to MP3, per newspaper

Minutes · real measurements

1 · Full skill (Claude)~20 min
2 · Fast + paid AI (Claude)2.35 min
3 · Fast + local AI (Ollama)~25–43 min

Stage 3 is slower than stage 2, but still faster than the original full skill — and with zero AI cost.

Why it got slower GPU

Paid AI processes the whole newspaper through a shared cache in the cloud; the local GPU (6 GB) has no room for that, so Speech AI now trims the text down to only the pages relevant to each topic — and even so, each call takes minutes, not seconds.

Quality: still behind Claude test

The 166/166 figure is from the Claude version. With the local model, real bugs were found and fixed (dates, currency conversion, non-literal quotes) — see Resilience and Costs, Part 3.

Editor's note: stage 2 took the mechanical work away from the AI; stage 3 takes away the cost, at the price of time and some quality — a deliberate trade-off, not a hidden limitation.

Part 2 · Input & Output

Input · input\

Two input folders, each with its own acceptance rules

Scripts · input\*.txt

Format

  • Text ready for narration, one file per audio.
  • UTF-8. Through the frontend, ANSI files (Notepad) are converted to UTF-8.
  • An empty or unreadable file is rejected or stays queued with an error.

Destination after processing

input\processados\YYYY-MM-DD\. If a same-named file already exists that day, the time is appended to the name.

Newspapers · input\Jornais\*.pdf

Newspaper identification

  • 1st by filename: "valor", "estadão", "estado de s. paulo", with or without accents.
  • 2nd by the PDF's front page, when the name doesn't help.
  • Not identified: skipped, with a warning in the run summary.

Recommendation

Keep "Valor" or "Estadão" in the PDF filename: Valor's front page has the newspaper name as an image, not as text.

Destination: input\Jornais\processados\YYYY-MM-DD\
Sources: app/script_inbox.py · skill_bridge/newspaper_inbox.py · web/server.py

1 · Reading

The PDF is copied to a plain filename before extraction: Git's pdftotext can't open accented paths on Windows. Each page becomes a text block.

2 · Filters

  • Discards pages with corrupted fonts and text-free ads.
  • Removes legal-notice lines, balance sheets and numeric tables.
  • Joins hyphenated words and cleans up PDF artifacts.

3 · Markers

Each page gets "=== [B7 · Companies] ===". That's how the AI cites the page and section in each slide's footer.

Step 2 · newsroom/editor.py · ollama_client.py

Five parallel calls, one single GPU: the bottleneck became the longest call

Duration of each call · Valor 10/08 (local AI)

Seconds · gemma3:4b via Ollama, 32,768-token context

2nd · Markets & macro1,440

2nd · Companies & sectors695

1st · Technology & AI211

Running in parallel, the step's duration is the longest call: 1,446.7 s in this run (24.1 min).

No cache, no full newspaper

Local AI doesn't have Anthropic's cloud context cache. Instead of the whole newspaper, each call gets only the pages most relevant to that topic (up to 5,000 words), chosen in Python by keyword — see next slide.

Guaranteed JSON output

Each call uses Ollama's local API with format = the JSON schema: slides, layout, KPIs, cards, quotes, sources and the audio paragraph for each slide — the same format used with Claude.

Lower reliability

With the local model, some calls only produce correct JSON on the 2nd try (up to 2 retries configured). Paid AI always closed on the 1st try, in the historical runs.

Accuracy

Only numbers, names and quotes from the text; opinions attributed to the author or the newspaper; the "Editor's note" is factual, with no partisan bias. Quotes are checked in Python against the sent excerpt — anything that doesn't match doesn't appear.

Keyword filtering local AI

Each topic (and each part) has its own list of terms in newsroom/profiles.py; pages with the most term hits go in first, up to the 5,000-word budget. That's how the 6 GB GPU gets only the essentials.

Merging

The parts of a topic are joined in order: slides, chips, "At a glance" numbers and agenda items.

Bug fixed: edition date

With the local model, the AI sometimes wrote the wrong date (copying the schema's example, e.g. "October 3, 4 and 5" on a different day's edition). The date is now read directly from the PDF's front page in Python — the AI no longer takes part in that step.

  • "US$ 1.4 tri" → "1.4 trillion dollars"

Operations · web\

Processing Hub: upload, process and track from the browser

What the page does 127.0.0.1:8000

  • Upload .txt and PDF files, with the newspaper identified instantly.
  • "Process texts" (--txt) and "Process newspapers" (--jornais) buttons, with an estimated-time confirmation (no AI cost).
  • Live log, steps, elapsed time and cancellation.
  • Audio files with a player and download; summaries with links to the HTML and the script.

How to start

Double-click start.bat (Windows) or ./start.sh (Git Bash). The browser opens on its own; Ctrl+C stops it.

RouteFunction
POST /api/upload/txtWrites to input\ (UTF-8)
POST /api/upload/jornaisWrites to input\Jornais\

POST /api/job/cancelStops the running routine
GET /api/filesQueues, audio and summaries

Editor's note: the server only accepts connections from the local machine and runs one routine at a time; while a run is in progress, removing files from the queue is blocked.

Failures

  • An item with an error doesn't stop the others.
  • A failed file stays in the input folder for the next run.
  • A failed AI call is retried (up to 2 times) — more common with the local model than with paid AI.

No account limit

With no per-token billing, there's no usage cap to hit: the factor limiting scale is now GPU time, not AI budget.

Plan B

With "engine": "agent", processing falls back to the full skill — still via Claude Code, still paid (~20 min); each run's log lands in logs\skills\.

Editor's note: processing both newspapers every business day of the year, paid AI would cost ~R$ 4,500/year; local AI's energy stays below R$ 12/year. See Paid AI vs Local AI.html for the full analysis, including the at-scale scenario (100 newspapers/day).

Roadmap · in priority order

Next steps

Part 1 · Capacity

More GPU: one 6 GB GPU sustains ~46 newspapers/day. Set a hardware budget before promising higher volume (see Paid AI vs Local AI.html).

Part 1 · Quality

Editorial review: listen to the audio and review the HTML output from the first weeks — the local model still trails Claude in density and precision.

Part 2 · Model

Re-evaluate the local model: if gemma3:4b's quality isn't enough, try qwen2.5:7b-instruct (a middle ground that still runs on the GPU).

Part 2 · Input

PDF filenames: keep "Valor" or "Estadão" in the name, since Valor's front page doesn't carry the name as text.

Part 3 · Operations

Scheduling: run python main.py automatically (or via .bat + Task Scheduler) every morning, after the PDFs arrive.

Part 3 · Version control

Commit to Git: none of these changes have been committed yet; review and version newsroom\, web\ and the configuration.
