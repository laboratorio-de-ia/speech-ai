Paid AI

Claude: today's engine

Which model, why it's used, what each call costs, and what that means across 100 newspapers a day, 365 days a year.

Section 1 · Paid AI

Paid AI · newsroom/editor.py

Claude Opus 5.5 writes the content; Sonnet 5.5 writes the cover

Why this model is used

1

Huge context, with caching

Each call receives the entire newspaper (176k to 354k tokens) and still responds in under 90 seconds — Anthropic caches the newspaper once, and every following call reads from there, at a fraction of the cost.

2

Editorial quality

Opus 5.5 follows the JSON schema precisely, keeps the topic hierarchy, and produces literal quotes with attribution. Fidelity test: 166 of 166 numbers verified against the newspaper's text.

3

Reliability

Across the 3 runs with saved reports, all 6 calls (3 topics + cover, 2 topics split into 2 parts) closed the JSON correctly on the 1st try, every time.

US$1.02

Real cost per newspaper (Valor, 10/06)

6 AI calls

96.6s

AI time per newspaper

Topics in parallel + cover

Cost structure cache

The 1st call writes the newspaper to cache (expensive); the rest read the cache (US$0.05 vs US$1.64 per call). This design is what makes US$1.02 per newspaper viable.

Why it's not "free"

Cost is per token processed in Anthropic's cloud — it grows linearly with volume. At 100 newspapers/day there's no shared cache between different newspapers: the cost per newspaper stays the same.

Executive take: paid AI is the quality and speed benchmark — the issue isn't what it delivers, it's the price of delivering it at volume.

Local AI

Ollama: zero cost, new limit

Which model, why it was chosen, what it costs (almost nothing), and why the real limit at 100 newspapers/day isn't money — it's GPU time.

gemma3:4b via Ollama6 GB GPU46 newspapers/day per GPU
Section 2 · Local AI

Local AI · newsroom/editor.py + ollama_client.py

gemma3:4b fits entirely on this machine's GPU — that's why it was chosen

Why this model is used

1

Fits the available GPU

The machine has only 6 GB of VRAM. gemma3:4b (3.3 GB) is the only one of the already-installed models (alongside deepseek-r1:8b) that loads entirely on the GPU; qwen2.5:72b and deepseek-r1:32b don't fit and spill onto the CPU — tested: a simple call took nearly 3 minutes just to load.

2

Zero cost per token

There's no charge per call: the only cost is electricity (next section), and it's negligible.

3

Trade-off accepted

The whole newspaper (up to 354k tokens) doesn't fit in the GPU's practical context. Speech AI now trims the text in Python, down to only the pages relevant to each topic (up to 5,000 words) before sending it to the model — an adjustment needed only because the AI is local.

Local AI · Capacity

100 newspapers/day need 51.7 hours of GPU — a day only has 24

The math that caps the scale

1

31 minutes per newspaper, one at a time

Ollama processes a newspaper's calls competing for the same GPU; there's no real parallelism gain on a single 6 GB card.

2

Maximum capacity: 46 newspapers/day

24h × 60 ÷ 31 min = 46.4 — the ceiling for 1 GPU running non-stop, 24 hours a day, 7 days a week.

3

100/day requires 2.2 GPUs

To avoid a growing backlog, at least 2 (comfortably, 3) GPUs like this one would need to run in parallel — or one much faster GPU (next section).

What happens if you ignore this

Running 100/day on just 1 GPU, the backlog grows by ~28h per day — within a week, the delay already exceeds 8 days. This isn't a tuning problem, it's a physical hardware limit.

Practical path

Combine more GPUs, use one faster GPU, or run a hybrid model (local for the base volume, paid AI for the day's overflow) — detailed in the GPU section.

Hardware · GPU

The current GPU sets the 46-newspapers/day ceiling — three paths to raise it

GPU in use today

NVIDIA RTX A3000 Laptop, 6 GB VRAM, ~35 W draw. A professional laptop GPU — not built to run large AI models; only gemma3:4b (4B parameters) fits comfortably.

1 · Switch to a bigger GPU

A dedicated 24 GB GPU (e.g., RTX 4090) runs larger, faster models — time per newspaper could drop from 31 to 6–10 min, raising one card's capacity to 140–240 newspapers/day.

2 · Multiple GPUs in parallel

2 to 3 GPUs like the current one (or fewer, larger GPUs) cover 100 newspapers/day with no backlog. The code already points to a configurable Ollama host — it just needs a simple dispatcher to split the queue across machines.

3 · Hybrid model

Local for the base volume (up to the available GPU's capacity) and paid AI only for the day's overflow — controls cost without risking delay when volume exceeds what the local hardware supports.

Tweaks that help without new hardware

Raise ollama_num_ctx only as much as needed (a larger context uses more VRAM and runs slower); use a slightly bigger but more accurate model (e.g., qwen2.5:7b) if the GPU can handle it; keep keep_alive high so the model isn't reloaded between calls.

Running via .bat (automation, not capacity)

A .bat file with Windows Task Scheduler processes the queue unattended — useful for 24h operation, but doesn't solve 1 GPU's 46-newspapers/day ceiling: see example on the next slide →

Operations · Automation

Unattended runs help operations; they don't increase GPU capacity

process_newspapers.bat

@echo off
cd /d "D:\CTO - Tecle\speech-ai"
:loop
python main.py --jornais
timeout /t 60
goto loop

Runs the queue continuously; each cycle processes whatever is in input\Jornais\ and waits 60 s before checking again. Stops with Ctrl+C.

Alternative: Task Scheduler

Create a Windows task that runs python main.py --jornais every N minutes — more robust than the loop above (restarts itself if the process crashes, logs run history).

What the .bat does NOT solve

Even running 24 hours a day, 7 days a week, non-stop, 1 GPU like this one processes at most 46 newspapers — running longer doesn't create extra capacity, it just uses 100% of what already exists.

Executive take: automation (.bat or Task Scheduler) is about running without someone watching — processing capacity is still a question of how many GPUs (and how fast) are available.

Conclusion · Direct recommendation

Local by default, paid as a relief valve

Financial

Keep local AI as the default: saves ~R$ 185.8k/year at this scale, with energy under R$ 800/year. The gap is too large to ignore.

Capacity

One 6 GB GPU sustains up to ~46 newspapers/day. For 100/day, invest in 2–3 GPUs (or 1 GPU with 24 GB+) before promising that volume.

Hybrid recommended

Process the base volume on the local GPU and route the day's overflow to paid AI — you only pay for what exceeds installed capacity.

Quality

Review local AI's HTML and script before publishing, at least in the first few weeks — reliability and content density still trail Opus.

Operations

Automate with .bat + Task Scheduler to run unattended — that solves operations, not capacity.

Next decision

Set the additional-GPU budget before committing to a 100-newspapers/day volume with a fixed deadline.
